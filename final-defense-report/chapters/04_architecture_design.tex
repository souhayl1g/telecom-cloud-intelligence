\section{System Overview}

The platform follows a cloud-native microservices architecture with seven containerized services communicating via REST APIs over an internal Docker bridge network. The architecture is designed for direct portability to \gls{hcs}.

\section{Data Flow Architecture}

The data pipeline follows a three-layer data lake pattern:

\begin{enumerate}
    \item \textbf{Raw Layer} (MinIO \texttt{raw/}): Unprocessed OSS and BSS data as generated/ingested
    \item \textbf{Processed Layer} (MinIO \texttt{processed/}): Cleaned, normalized, feature-engineered data
    \item \textbf{Curated Layer} (MinIO \texttt{curated/}): Joined OSS+BSS+AI results ready for analytics
\end{enumerate}

\section{Database Schema}

The PostgreSQL database contains eight tables organized around the \texttt{pipeline\_runs} parent table:

\begin{itemize}
    \item \texttt{users} --- Authentication and authorization
    \item \texttt{pipeline\_runs} --- Execution history (parent FK for all data tables)
    \item \texttt{dataset\_registry} --- Metadata for all data lake artifacts
    \item \texttt{model\_registry} --- ML model versioning and performance tracking
    \item \texttt{sla\_risk\_scores} --- SLA breach probability predictions
    \item \texttt{anomalies} --- OSS network anomaly detections
    \item \texttt{revenue\_anomalies} --- BSS revenue anomaly detections
    \item \texttt{correlation\_insights} --- OSS-BSS correlation results
\end{itemize}
