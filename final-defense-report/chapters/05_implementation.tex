\section{API Gateway Implementation}

The API Gateway (\texttt{services/api-gateway/main.py}) serves as the single entry point for all client requests. Built with FastAPI~\cite{fastapi2023}, it provides:

\begin{itemize}
    \item Seven REST endpoints for intelligence data retrieval
    \item JWT Bearer token authentication (verified against auth-service)
    \item Prometheus metrics instrumentation via \texttt{prometheus-fastapi-instrumentator}
    \item Raw SQL queries via \texttt{psycopg2} (no ORM overhead)
\end{itemize}

\begin{lstlisting}[language=Python, caption={API Gateway endpoint example}]
@app.get("/sla-risk")
async def get_sla_risk(request: Request):
    verify_token(request)
    conn = get_conn()
    cur = conn.cursor(cursor_factory=RealDictCursor)
    cur.execute("""
        SELECT score, region, explanation, model_version,
               created_at FROM sla_risk_scores
        ORDER BY created_at DESC LIMIT 1
    """)
    row = cur.fetchone()
    conn.close()
    return dict(row) if row else {"score": 0, "message": "No data"}
\end{lstlisting}

\section{Pipeline Worker Implementation}

The pipeline worker (\texttt{services/pipeline-worker/worker/\_\_main\_\_.py}) implements a 22-step ETL process executed every 120 seconds in daemon mode:

\begin{enumerate}
    \item Ensure MinIO buckets exist (raw, processed, curated)
    \item Generate synthetic OSS dataset with fault injection
    \item Generate synthetic BSS dataset with correlated revenue patterns
    \item Upload raw data to MinIO
    \item Register datasets in \texttt{dataset\_registry}
    \item Process and clean data
    \item Compute aggregate KPI features
    \item Call AI service for SLA risk prediction
    \item Call AI service for OSS anomaly detection
    \item Call AI service for BSS revenue anomaly detection
    \item Compute Pearson and Spearman correlations
    \item Build curated dataset (joined OSS+BSS+AI)
    \item Persist all results to PostgreSQL
\end{enumerate}

The daemon mode ensures continuous data flow:

\begin{lstlisting}[language=Python, caption={Pipeline daemon mode}]
if mode == "daemon":
    while True:
        try:
            run_once()  # Full 22-step pipeline
        except Exception as e:
            print(f"Error: {e}, retrying in 2 minutes...")
        time.sleep(120)  # 2-minute cycle
\end{lstlisting}

\section{Authentication Service}

The auth-service implements:

\begin{itemize}
    \item \textbf{Local authentication}: Email/password registration with bcrypt hashing
    \item \textbf{JWT tokens}: 24-hour expiry, HS256 signing
    \item \textbf{OAuth2 providers}: Google and GitHub social login
    \item \textbf{Role-based access}: viewer/admin roles stored in PostgreSQL
\end{itemize}

\section{Dashboard Implementation}

The dashboard is built with Next.js 14~\cite{nextjs2024} using the App Router pattern:

\begin{itemize}
    \item \textbf{15+ pages}: Overview, SLA Risk, Anomalies, Correlations, Pipeline Runs, Platform Health, Intelligence, Data Warehouse, L4 Agent
    \item \textbf{Real-time updates}: Auto-refresh every 120 seconds synchronized with pipeline cycles
    \item \textbf{Responsive design}: Horizontal top-nav layout with mobile tab switching
    \item \textbf{Theme support}: Dark/light mode with CSS custom properties
    \item \textbf{Command palette}: Ctrl+K search across all pages
\end{itemize}

Key visualization components include:
\begin{itemize}
    \item \texttt{RiskGauge} --- Circular gauge for SLA risk score
    \item \texttt{AnomalyHeatmap} --- Heat map of anomaly distribution
    \item \texttt{CorrelationHeatmap} --- OSS-BSS correlation matrix
    \item \texttt{SlaChart} --- Time-series SLA risk history
    \item \texttt{AnomaliesBarChart} --- Anomaly severity distribution
\end{itemize}

\section{Docker Orchestration}

All services are orchestrated via \texttt{docker-compose.yml} with:

\begin{itemize}
    \item Health checks for service dependency ordering
    \item Named volumes for data persistence
    \item Shared volumes for model artifacts between services
    \item Internal bridge network for service communication
    \item Environment-based configuration (no hardcoded secrets)
\end{itemize}
