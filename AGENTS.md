## MANDATORY RULES — APPLY EVERY TASK (no exceptions)

These rules are not suggestions. Violating them once costs hours of jury-defense credibility. Re-read this section before any change to dashboard, ai-service, or pipeline-worker.

### 1. Plan-first, always

- Before any `Edit`/`Write`/`NotebookEdit`: enter PLAN phase (Opus), produce a written plan (files · logic · risks · scope · verification), get user approval, **then** execute (Sonnet).
- "I planned in my head" is not a plan. "Trivial" tasks still get a 3-line plan.
- If any assumption surfaces during execution, **stop**, surface it, re-plan. Do not improvise structural changes.
- Skill source of truth: `~/.claude/skills/planning-before-execution/SKILL.md`. Enforced by SessionStart hook.

### 2. Honesty over decoration — no fake data, ever

- **No mocked metrics, no fabricated zeros, no synthetic timestamps.** Missing values render as `'—'`, never `0%` / `0.0` / `0` that looks real.
- Model metrics on `/model-evaluation` come from `notebooks/models/metrics.json` (generated by `scripts/dump_model_metrics.py`). If the JSON is missing, the route returns 503 with a remediation message. **No hardcoded constants fallback.**
- Trainer notebooks must write their honest values into `*_model_card.md`; the dump script parses them. `pb-retrain-model` re-runs the dump script automatically (api-gateway mounts `./scripts:/scripts:ro` + `./notebooks/models:/notebooks/models:rw`).
- Pipeline cycle duration = real wall-clock from `started_at` to `finished_at`. **Never fake an instant cycle.** Daemon mode (`RUN_MODE=daemon`, `CYCLE_SECONDS=120`) is the only acceptable production config; cycles typically take 70-180s of honest work.

### 3. Time everywhere = Tunis (UTC+1, no DST)

- Single util: `dashboard/lib/time.ts`. Use `formatTunisDateTime`, `formatTunisTime`, `formatTunisDate`, `formatTunisShortTime`, `durationSeconds`, `formatRelative`.
- **Never** call `new Date(iso).toLocaleString()` on a stored timestamp — it parses naive ISO as local TZ → off-by-one in Tunisia.
- The util force-appends `Z` when the ISO lacks a TZ suffix, then renders via `Intl.DateTimeFormat({timeZone:'Africa/Tunis'})`. Backend should still emit ISO with `Z`; the util is defence-in-depth.

### 4. ML feature contract = the joblib, not the code

- ai-service routers (`routers/v3/cem.py`, `rat.py`, `vae_anomaly.py`) load the feature contract from `*_feature_names.joblib` at startup via `model_cache.py`. Pydantic records accept `extra="allow"`; X is built in the order the joblib dictates.
- Pipeline-worker client (`worker/inference/v3_client.py`) passes through the full enriched record — the router cherry-picks. Missing fields default to `0.0`. Shape mismatch raises 422 loudly.
- Never hardcode a feature list in router code. Retraining with a wider feature set must not require a router change.

### 5. Sync this file with AGENTS.md

- After editing CLAUDE.md, copy it to AGENTS.md (or vice-versa). **They must be byte-identical.** Use `cp CLAUDE.md AGENTS.md`.
- This rule is mandatory. The two files are the single source of truth for any AI agent (Claude Code, Cursor, Continue, Aider, Codex, Cline) acting on this repo.

### 6. Verification before claiming done

- Frontend changes: start the dashboard, exercise the feature in a browser, watch the network tab + console. Type-check / unit-test pass is **not** proof of feature correctness.
- Backend changes: restart the relevant container, hit the endpoint via `docker compose exec`, paste the actual response. No "should work" assumptions.
- Pipeline changes: wait for a real 70-180s cycle, query `pipeline_runs` for `status='succeeded'` + sensible `finished_at - started_at`.

## Data Persistence (How It Actually Works)

- `pgdata` named volume persists across `make stop` / `restart` / `clean` — your data survives daily shutdowns.
- Wipe ONLY with `make nuke` / `make db-reset` / `docker compose down -v`.
- After any wipe, the `data-init` sidecar auto-runs on next `docker compose up`:
  - Counts rows in `bss_subscribers` / `oss_cell_kpis` / `subscriber_features`.
  - All non-empty → exits 0 fast (<1s skip path).
  - Any empty → runs `ingest_bss.py` + `ingest_oss_real.py` + `compute_features.py` (~10 min).
- Manual escape hatch: `make ensure-data` (host) or `docker compose run --rm data-init`.
- `SAMPLE_MONTH=""` empty signals the sampler to auto-detect latest month via `MAX(month_year)`.
- `services/pipeline-worker/worker/sampler.py` caches `_DEFAULT_MONTH_CACHE` on first call.

Mat views (`mv_*` created 2026-05-04) are PRODUCTION — do not drop. `mv_oss_by_cell` has unique index for CONCURRENT refresh.

## ADN L4 Agent (`dashboard/app/l4-agent/page.tsx`)

**Purpose:** Autonomous Driving Network Level 4 operations — auto-approves safe actions, requires human approval for risky ones. All actions are persisted to PostgreSQL (`agent_actions` table) and playbooks execute real backend operations.

### Auto-Approve Logic (`classifyAction`)
```typescript
function classifyAction(severity: string, type: string, confidence: number): boolean {
    // Returns true = needs human approval
    // Returns false = auto-approved
    if (type === 'remediation' && (severity === 'critical' || severity === 'warning'))
        return true;  // Human must approve
    return false;     // Auto-approve info/predictions
}
```
- **Auto-approved:** info actions, predictions (any confidence level)
- **Requires human approval:** critical/warning remediations

### Real Playbook Execution (via POST /actions/{id}/execute)
| Playbook ID | What It Really Does |
|-------------|-------------------|
| `pb-model-retrain` | POSTs to ai-service:8001/models/reload — force-reloads all 3 ML models from disk |
| `pb-anomaly-triage` | Queries recent anomalies, classifies by severity bands, cross-references correlations for root cause analysis |
| `pb-revenue-protect` | Queries high-severity revenue anomalies, extracts subscriber IDs/operators, computes total revenue at risk |
| `pb-sla-breach` | Reads current SLA score + explanation features, identifies which KPIs exceed thresholds |
| `pb-capacity-scale` | Computes real capacity metrics from KPI history, calculates headroom percentages |

All execution results stored in `execution_log` JSONB column of `agent_actions` table.

1. `generateActions()` creates actions from live platform data → POST /actions (persisted)

3. Approve: PATCH /actions/{id} → POST /actions/{id}/execute (real backend work)
4. Reject: PATCH /actions/{id} status='rejected'

## Working With This Codebase

### Adding a new API endpoint
1. Add route in `services/api-gateway/main.py`
2. Add DB query if needed (raw psycopg2, no ORM)
3. Endpoint auto-instrumented by prometheus-fastapi-instrumentator

### Adding a new ML model
1. Train in `services/ai-service/train_models.py`
2. Add inference endpoint in `services/ai-service/main.py`
3. Add pipeline step in `services/pipeline-worker/main.py`
4. Register model in `model_registry` table

### Frontend development
1. Pages in `dashboard/app/` (Next.js App Router)
2. Components in `dashboard/components/`
3. API calls go through `dashboard/lib/` utilities or `/api/*` routes
4. Auth middleware in `dashboard/middleware.ts`
5. Client pages needing auth data → use `/api/platform-data` SSR proxy (NOT direct :8000 calls)

### Build issues
- If you get "Cannot find module './948.js'" or similar: `rm -rf dashboard/.next && npx next build`
- This happens when `.next` cache is partially stale
- **Recharts MUST stay at v2.x** (pinned `2.15.3`). Recharts v3.x is a full TypeScript rewrite that causes React error #310 ("Objects are not valid as React child") because its internal Tooltip/Cell/Legend components use `useMemo` in ways that produce non-serializable objects through React's reconciliation pipeline. Do NOT upgrade to recharts 3.x.

## NeXo Architecture (Summary)

- **Orchestrator** (LLM-powered, Qwen2.5:7b via Ollama) routes intent → agent dispatch
